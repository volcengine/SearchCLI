## Commands

```bash
npm install
npm run dev
npm run build
npm start
```

The project is a single Next.js App Router application. The browser reads the
features selected by `vs project create --features` from `/api/config`, while
Viking credentials and resource IDs stay in server-only Route Handlers.

Generated credentials are written as plain text to `.env.local`, which is
ignored by Git. For deployments, prefer setting the same variables in the
runtime environment:

- `VIKING_API_KEY` for API key authentication
- `VIKING_AK`, `VIKING_SK`, and optionally `VIKING_REGION` for AK/SK authentication
- `VIKING_APP_ID` and `VIKING_FEATURES` for the application and enabled features
- `VIKING_SEARCH_SCENE_ID` and `VIKING_SEARCH_DATASET_ID` for search
- `VIKING_REC_SCENE_ID` for recommendation

The Route Handlers expose only the selected features and return HTTP 404 for
disabled features:

- `POST /api/chat` with `{ "message": "question", "sessionId": "optional-session-id" }`, returning a `text/event-stream` response
- `POST /api/search` with `{ "query": "keyword", "page": 1 }`, `{ "image": { "base64": "data:image/png;base64,..." }, "page": 1 }`, or both `query` and `image`
- `POST /api/query-recommendation`, returning recommended search queries in `recommendation_queries`
- `POST /api/recommend`, returning up to 20 recommendation results

Chat responses are streamed as SSE events: `session`, `chunk`, `error`, and `done`.
Successful search responses include pagination metadata from the template API.
Search query recommendation responses are returned directly from `@volcengine/search-sdk-js`.
Recommendation responses are returned directly from `@volcengine/search-sdk-js`.
